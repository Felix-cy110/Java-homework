## 迭代目标

在任务 6（资源 CRUD）、任务 7（Result 统一返回）、任务 8（Stream+Lambda+Optional）基础上，新增预约记录实体与预约业务流程，完成整套系统核心业务闭环。 实现学生提交预约申请、管理员审核预约；预约记录与资源状态联动；使用 Stream 完成预约数据查询；复用 Result 返回结构、自定义异常；本阶段仍未做三层分包，为任务 10 三层架构重构埋下耦合痛点。

## 验收标准（原文）

- 学生可提交预约申请；系统自动做时间段冲突校验，冲突时拒绝提交；
- 管理员可审核预约，通过 / 驳回；审核通过自动把资源置为占用；预约取消后资源恢复可预约；
- 学生只能查看、取消自己的预约；管理员查看全部预约；越权操作给出友好提示；
- 程序重启，预约记录不丢失；
- 全部预约查询逻辑使用 Stream+Optional；返回值统一为 Result；
- 业务闭环完整：用户登录→浏览资源→提交预约→管理员审核→资源状态变更→可取消预约。
