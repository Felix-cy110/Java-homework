## 迭代目标

解决V1.0账号硬编码、无法新增用户的问题，实现动态注册功能，使用集合管理用户数据。

## 验收标准（原文）

- 可正常注册学生账号，同名账号无法注册，注册成功后可登录。

## 基线、问题与方案

- 继承源码提交：`6c3bb722373b7e1130b11dfc934f3f5eeea4b064`（任务 1）；开始任务 2 时仓库 HEAD 为 `f2e36de6954d94c7d9c1b43785bb8243f804e394`，工作区干净。
- 原有问题及原因：任务 1 在条件分支中固定两组账号，无法新增用户；每次启动只校验一次，也无法完成同次运行中的注册与登录。
- 本次方案：在本目录继承 `SystemMain.java`，保留 `Scanner` 整行输入、输入结束处理和资源自动关闭，加入首页循环与 `HashMap<String, String>`，以注册数据替换固定账号，抽取账号和密码校验方法。
- 设计原则：在同一主类中将数据合法性校验与交互流程分离，落实本阶段的单一职责原则；继续使用过程式控制流与集合，不提前引入实体类、分层或设计模式。
- 保留历史：任务 1 源码保持原样，只补记已发生的用户验收和源码提交信息。

## 交付物与本阶段行为

- [SystemMain.java](src/SystemMain.java)：本阶段全部 Java 代码，只有一个主类；在原入口中扩展菜单、集合和注册逻辑，新增两个独立校验方法，附精简中文注释。
- 本 README：需求对应、继承与变化记录、运行命令、测试和用户验收说明。无需其他任务的源码或运行数据。
- 首页循环提供 `1.登录`、`2.注册`，并增加 `0.退出` 方便结束本次运行。注册或登录结束后回到首页，非法选项会提示并允许重选；循环及退出选项是支持本阶段操作的实现细节。
- 账号在注册和登录时都执行非空校验；不合法时直接返回首页，不再询问密码。注册密码必须非空且原始输入长度至少为 6；密码校验或重名校验失败时，不插入也不修改集合。
- 账号和密码均按完整一行读取，保留前后及内部空格，比较时区分大小写；非空校验使用 `trim()` 判断，因此空字符串、仅含普通空格或制表符的输入不合法。菜单选项单独去除前后空白。这些是实现细节，不新增教师规则。
- 登录从集合取得对应密码并精确匹配；未知账号或错误密码均提示 `登录失败：账号或密码错误。`，匹配成功提示 `登录成功，欢迎学生！`。
- 相比任务 1，固定管理员和学生账号按任务 2 原文删除，不能再用未注册的 `admin / 123456` 或 `student / 123456` 直接登录。输入结束时仍友好退出，`Scanner` 仍自动关闭。
- 没有运行数据文件或配置文件；账号仅存在当前 JVM 的内存中，退出重启后集合重新为空。`out/` 仅保存编译产物，已由根目录忽略规则排除。

## 环境与编译运行

实际验证：Windows x64、Oracle JDK `1.8.0_341`（`D:\jdk8`），`java` 与 `javac` 版本均为 `1.8.0_341`。显式调用 JDK 8，不依赖系统默认 Java 版本。换电脑时替换 JDK 与项目路径。

在 PowerShell 中执行：

```powershell
Set-Location 'D:\MyProject\Java-homework\任务02-V1.1-用户注册功能'
New-Item -ItemType Directory -Force -Path out | Out-Null
& 'D:\jdk8\bin\javac.exe' -encoding UTF-8 -Xlint:all -classpath out -d out src\SystemMain.java
if ($LASTEXITCODE -ne 0) { throw '编译失败，请先检查上方错误。' }
chcp 65001 | Out-Null
& 'D:\jdk8\bin\java.exe' '-Dfile.encoding=UTF-8' -cp out SystemMain
```

源码和上述终端运行均使用 UTF-8；`-classpath out` 将项目依赖限定到本目录的编译输出，避免本机旧 classpath 干扰。只需 JDK，不使用第三方框架、测试库或构建工具。
