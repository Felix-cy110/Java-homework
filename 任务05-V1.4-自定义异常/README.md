## 基线、问题与方案

任务 4 已有中文失败提示，没有在业务分支直接打印 Java 堆栈，但失败处理分散，无法以异常类型区分业务原因；文件失败提示还会拼接底层异常信息。本任务在独立目录继承其源码，增加业务异常父类与四种子类，由校验、注册、登录主动抛出，入口按父类型统一捕获。

- 在 `SystemMain` 内抽出 `registerUser`、`loginUser` 和抛出异常的校验方法，业务方法不打印提示，成功返回用户对象；注册仍先保存候选集合，成功后才更新内存。
- `main` 每次菜单操作统一捕获 `BusinessException`，显示中文提示后继续菜单。所有子类型共用此分支，不按异常名称逐一判断。
- 保存失败由入口捕获 `IOException`，提示系统错误并允许重试；启动加载失败和未预期运行时错误由入口外层捕获，显示固定中文提示并以退出码 1 停止。系统错误不展示 `e.getMessage()` 或堆栈。
- `User.java` 和 `FileUtil.java` 继承任务 4；本次只增加包声明、必要导入并同步注释，文件格式、转义、临时文件替换、角色和注册时间处理保持原样。没有复制旧任务账号数据或编译输出。
- 新异常类、修改的方法、关键捕获逻辑与脚本均有精简中文注释。当前按用户要求使用 `com.campus.reservation` 根包及职责子包，通过 JDK 与原有脚本编译运行。
