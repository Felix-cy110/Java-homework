# Java-homework

软件构造综合实践课程作业：校园资源预约系统。使用一个仓库保存 20 个迭代任务，每个任务目录对应一个独立 Java 项目，后一个项目基于前一个项目增量开发。

当前状态：仅完成仓库与目录初始化，20 个任务均待实现。

## 目录约定

目录使用 `任务编号-版本-任务名` 命名；编号补零便于排序，标题中的冒号统一替换为短横线。

```text
Java-homework/
├── README.md
├── AGENTS.md
├── .gitignore
├── .gitattributes
├── .github/pull_request_template.md
├── 项目任务列表.docx
├── 评分标准.docx
├── docs/需求核对.md
├── 任务01-V1.0-项目初始化/
│   ├── README.md
│   └── src/
├── 任务02-V1.1-用户注册功能/
│   ├── README.md
│   └── src/
├── …
└── 任务20-V6.0-项目视图拓展/
    ├── README.md
    └── src/
```

根目录只管理 Git 和全课程说明。每个任务目录拥有自己的源码、运行说明及后续需要的配置、测试和文档，不引用其他任务目录。运行程序时以对应任务目录作为工作目录，避免不同版本共用持久化文件。

目前 `src/` 仅通过 `.gitkeep` 保留空目录，不代表已实现源码。各版本源码包含重复类名，应分别导入 IDE、编译和运行，不要把 20 个 `src/` 合并为同一个 Java 项目。

## 迭代方式

1. 按任务编号顺序开发，先完成并验收当前任务，记录实际测试结果。
2. 开始下一任务时，继承上一任务已验收的源码，再做本次增量修改；不带入编译产物、IDE 本机配置或运行数据。
3. 保留已完成目录的阶段成果，不把后续功能倒灌到早期任务。每个任务提交说明中记录本次新增、重构和回归结果。
4. 根仓库统一管理提交历史，任务目录内不再初始化 Git。需要独立交付时，仅交付对应任务完整目录及其说明。

## 开发与验收约束

- JDK 8 及以上、原生 Java、无第三方框架；任务 1 按任务书的 JDK 8 环境验证。
- 任务 1 全部代码放在 SystemMain；任务 7 仍不分包分层；任务 10 才进行三层架构重构；任务 13 再演进为 MVC。
- 控制台版本为必做基线；任务 20 的视图拓展为选做加分，新增视图必须遵守核心业务不改的约束。
- 任务 10 和任务 13 分别提交三层架构、MVC 的 UML 类图。结题需提交源码、实践报告和演示录屏。
- 运行时用户、资源、预约及日志文件已纳入忽略规则；需要版本管理的演示数据放入各任务的 `samples/`，并说明加载方式。
- 暂无 Java 源码，因此当前不提供或声称通过任何业务编译、运行及功能测试；实现后在各任务 README 中补齐实际命令和结果。

## 提交与 PR

提交信息、PR 标题遵循 [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/#specification)，描述使用中文，例如：

```text
feat(task01): 实现管理员和学生登录
fix(task02): 修复重复用户名校验遗漏的问题
refactor(task10): 完成三层架构重构
docs(task13): 更新 MVC 类图与运行说明
```

PR 正文使用中文，写清原有问题、产生原因、当前解决方案、测试方法及结果。未执行的测试需如实说明原因，模板位于 [.github/pull_request_template.md](.github/pull_request_template.md)。
