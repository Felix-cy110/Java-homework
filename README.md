## 目录约定

目录使用 `任务编号-版本-任务名` 命名；编号补零便于排序，标题中的冒号统一替换为短横线。

```text
Java-homework/
├── README.md
├── LICENSE
├── CONTRIBUTING.md
├── AGENTS.md
├── .gitignore
├── .gitattributes
├── .github/pull_request_template.md
├── 项目任务列表.docx
├── 评分标准.docx
├── docs/需求核对.md
├── 任务01-V1.0-项目初始化/
│   ├── README.md
│   └── src/
├── 任务02-V1.1-用户注册功能/
│   ├── README.md
│   └── src/
├── …
└── 任务20-V6.0-项目视图拓展/
    ├── README.md
    └── src/
```

根目录只管理 Git 和全课程说明。每个任务目录拥有自己的源码、运行说明及后续需要的配置、测试和文档，不引用其他任务目录。运行程序时以对应任务目录作为工作目录，避免不同版本共用持久化文件。

按用户 2026-11-10 的要求，后续阶段同时继承已有业务数据，写入新任务自己的独立副本。格式兼容时复制或合并，格式或存储方式变化时优先转换迁移；目标已有数据先备份并核对冲突，确实无法迁移的部分保留原数据并说明原因。运行数据及备份继续排除在 Git 之外，详见[迁移约定](AGENTS.md#阶段间持久化数据迁移)。

按用户最新要求，任务 03–08 在 `src/com/campus/reservation/` 下按职责组织 Java 包：入口位于根包，任务 03 有 `entity`，任务 04 增加 `util`，任务 05 增加 `exception`，任务 06 继承此结构扩展资源功能，任务 07 在 entity 中增加 Result，任务 08 继承该包结构继续演进。继续使用 JDK 与现有脚本编译运行，不引入 Maven 或框架。任务 1、2 保留原状；口径来源见[需求核对](docs/需求核对.md)。

任务 01–08 已有各阶段源码；任务 09–20 的 `src/` 仅通过 `.gitkeep` 保留空目录，不代表已实现源码。各版本源码包含重复类名，应分别导入 IDE、编译和运行，不要把 20 个 `src/` 合并为同一个 Java 项目。

任务 03–08 分别提供 OpenIDEA 配置“任务03：编译并运行”至“任务08：编译并运行”，打开仓库根目录或对应独立任务目录均可选择；各自只编译、运行当前任务。运行命令见各任务 README；持久化文件保存在各自任务目录。任务 06–08 提供演示用户、资源及最小预约关联，导入方式见对应 README，已有数据不会自动覆盖。

## 迭代方式

1. 按任务编号顺序开发，先完成并验收当前任务，记录实际测试结果。
2. 开始下一任务时，继承上一任务已验收的源码和持久化业务数据，再做本次增量修改；数据先备份并验证兼容性，必要时转换迁移，不带入编译产物、IDE 本机配置或无关本机凭据。
3. 保留已完成目录的阶段成果，不把后续功能倒灌到早期任务。每个任务提交说明中记录本次新增、重构和回归结果。
4. 根仓库统一管理提交历史，任务目录内不再初始化 Git。需要独立交付时，仅交付对应任务完整目录及其说明。

## 提交与 PR

提交信息、PR 标题遵循 [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/#specification)，描述使用中文，例如：

```text
feat(task01): 实现管理员和学生登录
fix(task02): 修复重复用户名校验遗漏的问题
refactor(task10): 完成三层架构重构
docs(task13): 更新 MVC 类图与运行说明
```

PR 正文使用中文，写清原有问题、产生原因、当前解决方案、测试方法及结果。未执行的测试需如实说明原因，模板位于 [.github/pull_request_template.md](.github/pull_request_template.md)。
