## 迭代目标

在 MVC 架构、反射工具、注解日志、Stream 统计基础上，引入JDK 线程池 ThreadPoolExecutor，将耗时操作改为异步执行；同时修复内存集合多线程读写带来的并发问题，增加并发安全控制。

场景：日志持久化、统计报表计算属于 IO/CPU 耗时操作，放到异步线程执行，不阻塞控制台主线程。 学习要点：线程池创建、任务提交、Runnable 任务、并发安全、锁机制。 不新增业务菜单，原有业务逻辑不变，只做并发与异步重构。

## 验收标准（原文）

- 存在ThreadPoolUtil全局线程池工具，静态初始化、私有构造；
- 日志保存操作提交线程池异步执行，控制台交互不会被文件 IO 阻塞；
- 内存集合增加并发安全控制，多线程读写不会抛出并发修改异常；
- 多线程并发写入日志文件，日志内容不会错乱、覆盖；
- 程序关闭时正常关闭线程池，等待异步任务完成；
- 原有所有业务功能正常，异步逻辑不影响业务结果。
