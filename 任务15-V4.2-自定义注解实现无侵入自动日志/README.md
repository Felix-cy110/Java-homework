## 迭代目标

在 MVC 架构、Stream 统计、预约状态机基础上，采用自定义注解 + 反射手写简易 AOP 思想，实现业务操作日志自动记录。 解决日志代码硬编码散落在 Service 方法内、污染业务逻辑的问题。只需要在业务方法上添加注解标记，无需修改业务主体代码，即可自动捕获操作人、入参、返回结果、异常信息并持久化；日志属于横切关注点，和业务逻辑解耦。

限制：不引入 Spring、AspectJ 等第三方框架，纯 JDK 原生 API 实现，适配课程教学。原有资源预约、统计报表功能保持不变。

## 验收标准（原文）

- 自定义注解@OperationLog可以在运行时被反射识别，成功读取注解描述；
- 被注解标记的业务方法执行时自动生成日志，日志包含全部必填字段；方法抛出异常时自动捕获异常信息写入日志；
- 日志持久化到operation_log.txt，重启程序日志不丢失；
- 管理员可查看全部日志，支持按用户名筛选；学生无日志查询权限；
- Service 业务代码没有日志硬编码，日志收集逻辑全部放在 LogAspect 切面；
- 原有全部业务、统计报表功能不受日志切面影响，正常运行。
