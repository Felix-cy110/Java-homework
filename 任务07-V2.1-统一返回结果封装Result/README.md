## 迭代目标

前面任务中，方法返回值五花八门（有的返回 boolean、有的返回对象、有的返回 null，异常直接抛出）。

本次迭代：封装统一响应结果类 Result，标准化所有业务方法的返回值，统一区分成功 / 失败、提示信息、返回数据，减少裸返回 null、boolean 的写法；为后续异常处理、控制台交互做统一规范。

注意：本阶段仍然未做三层架构分层（三层重构在任务 10），本次只解决返回值标准化问题，不重构包结构，保留当前代码耦合，作为后续重构的铺垫。

## 验收标准（原文）

- 存在泛型 Result<T>类，静态 success/fail 工厂方法可用；
- 用户、资源模块全部业务方法改造完成，统一返回 Result；
- 控制台菜单根据 Result 对象判断操作结果，输出友好提示；
- 各种失败场景（资源不存在、权限不足、参数为空）都能返回对应的失败消息，程序不崩溃；
- 原有持久化、用户权限、资源 CRUD 功能**全部保留，功能不变**，只是返回值标准化。

- [Result.java](src/com/campus/reservation/entity/Result.java)：三个私有字段、四个泛型静态工厂、访问方法及 `toString`。类只承载结果，不读文件、不输出菜单。
- [SystemMain.java](src/com/campus/reservation/SystemMain.java)：9 个业务方法统一返回结果；自定义业务异常和预期 IO 失败在操作边界转换为失败结果，菜单用 `isSuccess()` 控制流程，用 `getMsg()` 和 `getData()` 展示。
- [run.ps1](run.ps1)、[独立任务配置](.openidea/run.toml)、[仓库根配置](../.openidea/run.toml)：递归编译全部 13 个 Java 文件，以完整主类名启动。
- [演示用户](samples/user-demo.txt)、[演示资源](samples/resource-demo.txt)、[演示关联](samples/reserve-demo.txt)：沿用明确的演示值，不自动导入。

| 业务方法 | 结果类型 | 成功数据 |
| --- | --- | --- |
| `initializeDefaultAdministrator` | `Result<Void>` | 无 |
| `registerUser`、`loginUser`、`findUserByUsername` | `Result<User>` | 注册、登录或查到的用户 |
| `addResource`、`updateResource`、`findResourceById` | `Result<CampusResource>` | 新增、修改或查到的资源 |
| `queryResources` | `Result<List<CampusResource>>` | 按角色过滤的资源集合，可为空 |
| `deleteResource` | `Result<Void>` | 无 |

`success(T data)` 使用默认消息“操作成功。”；`success(String msg)` 只携带消息；`success(String msg, T data)` 同时携带消息与数据；`fail(String msg)` 的 data 始终为 null。getter/setter 保持失败不携带数据：设为失败时清空 data，失败状态下设置 data 也不会保留；手动填充成功结果时先调用 `setSuccess(true)`。

Java 会把单个 String 参数优先匹配到消息重载，因此字符串作为数据时使用 `Result.success("查询成功。", "字符串数据")`。用户、资源和列表则可直接使用数据重载。

新增和修改的成功提示与资源详情分行显示，以统一消息与数据的展示入口；其余菜单编号、中文提示及业务规则保持。空列表是成功查询，显示“暂无符合条件的资源。”；操作失败时只展示原因，不打印空对象或底层堆栈。输入校验仍可中断未填完的表单，登录失败不会进入资源菜单。

本轮应用泛型封装与静态工厂方法，减少调用方手工组合结果字段；`Result` 只负责返回结构，业务与文件职责保持当前阶段边界。未将这些工厂方法表述为已经实现后续 DaoFactory 或三层架构。
