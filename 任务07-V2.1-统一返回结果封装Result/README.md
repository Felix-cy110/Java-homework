## 迭代目标

前面任务中，方法返回值五花八门（有的返回 boolean、有的返回对象、有的返回 null，异常直接抛出）。

本次迭代：封装统一响应结果类 Result**，标准化所有业务方法的返回值，统一区分成功 / 失败、提示信息、返回数据，减少裸返回 null、boolean 的写法；为后续异常处理、控制台交互做统一规范。

注意：本阶段仍然未做三层架构分层（三层重构在任务 10），本次只解决返回值标准化问题，不重构包结构，保留当前代码耦合，作为后续重构的铺垫。

## 验收标准（原文）

- 存在泛型 Result<T>类，静态 success/fail 工厂方法可用；
- 用户、资源模块全部业务方法改造完成，统一返回 Result；
- 控制台菜单根据 Result 对象判断操作结果，输出友好提示；
- 各种失败场景（资源不存在、权限不足、参数为空）都能返回对应的失败消息，程序不崩溃；
- 原有持久化、用户权限、资源 CRUD 功能**全部保留，功能不变**，只是返回值标准化。
